# CrewPilot — submission and evidence checklist

## Official challenge fit
- [ ] Selected track: Best Business Workflow.
- [ ] A real human uses team chat and collaborates with at least one real AI agent through Switch.
- [ ] A real task is completed (not just a chatbot answer).
- [ ] README explains Switch architecture and why the workflow depends on it.
- [ ] Existing Auto-Triager is labelled pre-existing; new event work is clearly identifiable in commits/docs.

## Implementation proof
- [ ] Public GitHub repository URL.
- [ ] Branch and commit history for event work.
- [ ] Three independent Switch agent identities: Triager, Reproducer/Builder and Reviewer; capture names/roles in Switch UI.
- [ ] Reproducer/Builder demonstrates a real failing case before implementing its approved fix; capture exact command and sanitized output.
- [ ] Shared Switch room with a human participant.
- [ ] Genuine Switch messages showing triage, approval, handoff, Builder report and Reviewer report.
- [ ] Real issue URL/number and task ID.
- [ ] Actual changed files/diff and branch/commit SHA.
- [ ] Actual test commands, output, exit codes and CI run URL.
- [ ] Reviewer verdict tied to the exact commit SHA.
- [ ] Human PR-publication approval tied to the exact SHA.
- [ ] Real GitHub Draft PR URL/number (never a fabricated placeholder).

## Reproducibility
- [ ] Clean-clone setup documented and tested.
- [ ] Supported Python version and dependency installation documented.
- [ ] Docker/Switch server version, API URL vs Gateway URL distinction and chat bridge setup documented.
- [ ] Required provider credentials listed by variable name only; no secret values committed.
- [ ] Agent registration, addressing permissions and startup commands documented.
- [ ] Tests and quality checks work in a clean environment.
- [ ] Known limitations and fallback behavior documented.

## Demo
- [ ] Demo shows the real team chat, the Switch room, distinct agent identities and real handoff messages.
- [ ] Demo shows the human approval gates.
- [ ] Demo shows a real code diff, real test result and independent review.
- [ ] Demo shows the real Draft PR in GitHub.
- [ ] Walkthrough is no longer than 5 minutes and is uploaded in a supported format (MP4, MOV or WebM; portal limit 500 MB).
- [ ] Cover image is 16:9.
- [ ] Up to five useful screenshots are selected for the gallery.
- [ ] Recording has clear narration, readable screen zoom and no exposed secrets/private data.
- [ ] Video link is accessible to judges and placed in README/submission form.

## Submission administration
- [ ] Participant registration complete with accurate identity.
- [ ] Team size at or below four; each participant meets the official age/eligibility rules.
- [ ] Join WeMakeDevs Discord; check the official submission process/portal.
- [ ] Wooble Proof Brief Start step: project title and type selected (Software).
- [ ] Wooble Show it step: walkthrough video uploaded, 16:9 cover added, useful screenshots attached.
- [ ] Wooble Explain it step: Problem, Approach, Result and Reflection written; project explanation is at least 150 characters.
- [ ] Wooble Your part & links step: role is within 60 characters; one-liner is within 160 characters; team roles are entered accurately and confirmed by teammates; up to three outcomes are evidence-backed; technologies and AI tools used are selected truthfully.
- [ ] Wooble Review step: all required fields are complete; preview checked; final Submit action performed deliberately.
- [ ] Submit public repository, demo video and README before 2026-11-07 23:59 IST.
- [ ] Save the confirmation/receipt/screenshot of the actual submission.

## Optional side tracks
- [ ] Best Blog: publish an accurate build walkthrough; keep it helpful to first-time Switch users.
- [ ] Code with Wispr: only claim entry if Wispr Flow was actually used to build and the required Insights scorecard screenshot is attached.
- [ ] #HowISwitch social post is optional; it is not a substitute for the main submission.
