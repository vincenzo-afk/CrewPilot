# Hackathon Compliance and Evidence

## Official requirement mapping
- A real person and at least one AI agent collaborate through Switch in a supported team chat to complete a real task.
- Switch must be essential to the product, not a decorative chat adapter. The README must explain how Switch is used.
- Provide a reproducible project with clear setup. The official event schedule calls for a public GitHub repository, demo video and README before the deadline.
- Judging dimensions shown on the official page: Use of Switch, Technical execution, Creativity and impact, Presentation. The current page renders numeric weights as 0%; do not invent percentage weights.
- Existing agents/libraries are allowed, but the Switch setup and the workflow the agents run must be built during the hackathon.

## Evidence rules
- Distinguish pre-existing baseline, new hackathon code, mocked tests and live verification.
- Never fabricate a Switch screenshot, chat message, agent identity, run log, test result, commit, PR URL or CI status.
- For each task record: issue URL/ID, triage result, human approvals and actor IDs, Switch message/handoff IDs, branch, commit SHA, exact test commands/output/exit codes, Reviewer verdict and reviewed SHA, PR URL/number and timestamp.
- Remove secrets and private data from committed evidence. Use a public/synthetic demo issue where practical.

## Submission pack
Maintain README, architecture diagram, setup guide, security note, test instructions, demo script, limitations, team/track details, screenshots and demo video link. Confirm the official submission portal/process from the event page or organizer Discord; do not invent a submission URL.
